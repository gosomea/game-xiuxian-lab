# 剑术三方向探索方案

使用者授权实施三个方向，由原生子 Agent 分别实现，主 Agent 集成与验收。目标是 [[goal:wheel]]、[[goal:giant]]、[[goal:rain]] 和共同的 [[goal:quality]]。

现状：三招与五根木桩可运行；Compatibility / Godot 4.6；共享修士和 CameraRig。新增天轮强调双层圆轮与分组弧线齐射，巨剑强调凝聚悬停后的加速镇落，剑雨强调选区和分批降剑。各自独立能力包、Component 与 View，允许释放后换招继续完成；不扩展成完整战斗循环。

选择三独立行为包，先完善共享瞄准、三维命中、取消序号、反馈请求与轻量视觉工具。未选择一个巨型 SwordArray、逐剑物理节点或变更全局渲染器。所有运行时改动先由 owning note 覆盖。

执行顺序：[[node:preflight]] → [[node:foundation]] → [[node:wheel]] / [[node:giant]] / [[node:rain]] → [[node:integration]] → [[node:acceptance]]。三条实现使用基于相同共享基础的独立 worktree；主工作区集成，冻结的分支与基础不再修改。

验收条件：

1. 完整阶段可观察：凝聚→悬停/成阵→释放→命中→消散，快速松开有有效简版；冷却与重复施法不会叠加失控。
2. 运动自然：入阵和转向连续，释放有加速，剑尖随轨迹，落点明确；不能出现传送、反向飞行、抖动或穿过地面后仍飞。
3. 画面有层次：法阵、剑形、轨迹、冲击各可辨；人物与落点保留；主剑完整可见，天轮不退化成扇面，剑雨能看清批次；960×600 和 1280×800 均可操作。
4. 机制正确：高速竖直贯穿可命中，范围高度受限；每剑每目标及巨剑单次镇落去重；不同高度地形正确选点；持续法术释放后换招可完成，蓄势换招、失焦、R 与退出清账。
5. 集成完整：旧三招、移动、跳跃、御剑与镜头保持可用；不新增血量/伤害/胜负；无脚本/资源错误，门禁和负向控制通过。
6. 帅气判据由主 Agent 看真实窗口连续画面并记录理由；数学轨迹与阶段样本辅助审查。用户个人喜好仍可后续调节，不用测试结果宣称用户主观认可。

证据：各分支配对测试、完整运行时与 Tier 0 日志、真实输入流程、截图序列/动图、数值节奏样本和语义评审；保存全部新资产及验收图，使用本地 commit，不推送。
