### 关键结论与坑（照做可省一轮）

**自动绑骨服务**：是 `Make-It-Animatable`，**不在本机**。`http://127.0.0.1:7860/` 无监听；
真实地址 `21.6.90.117:7860`（经 utun6 可达）。`tools/art/port_forward_mia_7860.py` 可转发本机 7860。
它接受 `.glb`，因此 599K 网格**直接绑骨**，无需低面代理，也无需权重转移。
（上一轮 handoff 记录的 Mixamo Auto-Rigger 服务端卡死是真实历史，已改用此服务绕开。）

**手作姿态**：库中没有打坐/负手/御剑，最近的气质都不对，因此**在本骨架上手工摆姿态**
（`tools/art/author_cultivator_pose.py`）。手调欧拉角会失败且失败只在渲染里可见：
实测 `LeftArm` 绕 X +45° 让手向**外上方**走而非前抬，按直觉写的「后旋」把手举到了头顶。
因此配套了求解器 `tools/art/solve_pose_targets.py`（坐标下降 + 关节限位），把误差变成厘米数。

**骨架硬边界**：22 骨、**无手指骨**。掐诀/结印/剑诀这类以手型为核心的动作**做不出来**，
最多到「手叠手」。要突破须先加手指骨并重绑权重——那是另一轮工作，不要在现有骨架上再试。

**躯干后仰的真因**：不是本仓库引入的。服务原产的 `clip_idle_slot1.glb` 就是 13.86°，
说明是自动绑骨继承来的。修法**必须写在构建期、导出之前、内存中**
（`tools/art/cultivator_lean_fix.py`，被 build 脚本导入）。第一版做成独立工具（导入 FBX → 改 → 导出 FBX）
造成三个连锁缺陷，根因只有一个：**Blender 的 FBX 导出器总会把 armature 物体变换烘成动画轨道**，
下游地面位移对那条轨道又加一次 → 浮空 1.09m；清空物体动画会连骨骼动作一起清掉 → 构建报
`import produced no action`；重设基线补偿 → 变成 3 倍。**不要再把矫正规避到 FBX 往返里。**

**跑步转歪**：`Run.fbx` 的 retarget 把角色系统性转了 32°（髋部 yaw 全程 +22.7~+39.3，
其它 clip 都在 0 附近）。`Running.fbx` 是 +113.7°，三个候选都坏——这是**逐 clip 的偶发风险**，
不是流程性错误。因此给 `tools/art/score_mia_clip.py` 加了**髋部 yaw 偏差**判据，
换 clip 时必跑。已改用 `Sprint.fbx`（−2.1°），run 参考速度随之重测为 **2.0305 m/s**。

**速度标定**：走 1.55 / 疾行 2.25 m/s，与各自 clip 的自然速度（1.288 / 2.0305）对应；
切换阈值 `RUN_SPEED_MPS = 1.9` 取两档中点。改动作或改帧率后**必须重跑步幅量具**，否则滑步会回来。

**一个真 bug**：`movement_garden.gd` 引用了未声明的 `KEY_SPRINT`，**整个脚本解析失败、场景加载不出来**。
该场景自带输入表、不加载 `MovementLabInput`，因此在本地声明。修测试时若发现某场景「装配失败」，
先查是不是这类解析错误，而不是物理参数。
