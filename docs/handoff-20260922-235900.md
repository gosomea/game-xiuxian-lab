# Handoff: v9 贴地修复——「斜」被拆成两个问题，其中一个已修（2026-09-22）

## Current state

### 使用者报告了什么

> 这个角色依然是斜着的，不是踩着地面的。

上一轮（Phase 8）处理过「斜」，用的判据是**髋→头轴**（躯干）偏离竖直的角度，并把 idle
从 12.81° 压到 1.71°。所以本轮先回答的问题是：**躯干已经竖直了，为什么同一句反馈仍然成立。**

答案是：这句话里有两个独立缺陷，上一轮只修了其中一个，而且两个都没有对应的量具。

### 拆解与结论

| 问题 | 判据 | 本轮结论 |
|---|---|---|
| 躯干是否竖直 | `measure_glb_upright.py` / 以骨盆为参考系 | **正常**（1.70–3.12°），上一轮确实修好了 |
| 角色是否踩在地面 | **此前无量具** | **浮空 4–7 cm，已修**（提交 `649d829`） |
| 骨盆是否站在双脚上 | **此前无量具** | 前移 0.154 m（被接受的 v7 为 0.051 m），**已量、未修** |
| 头偏离踝铅垂线 8.3° | `render_upright_check.py --anchor ankle` | **不是缺陷**：被接受的 v7 报 10.3°，该角度由站姿解剖学自然偏移构成 |

「斜着」的观感 = 浮空（已修）+ 骨盆前移带来的整体后倾观感（未修，原因见下）。

### 为什么浮空

构建期的地面位移取「各 locomotion clip 最低点的**最小值**」。这个统计口径必然让**恰好一个**
clip 贴地、其余 clip 各自浮空 (自身最低点 − 最小值)。逐 clip 量蒙皮网格最低顶点：

| clip | 修正前 | 修正后 |
|---|---|---|
| `idle` | +0.0673 m | −0.0000 |
| `walk` | +0.0410 m | −0.0000 |
| `run` | +0.0168 m | −0.0000 |
| `idle_guarded` | +0.0726 m | −0.0000 |
| `meditate` | +0.0725 m | +0.0000 |
| `sword_ride` | +0.0726 m | −0.0000 |
| `jump`（腾空，不参与标定） | +0.0793 m | +0.0793 m |

对照基线：同仓 `cultivator_neutral_youth_v7` 与 `cultivator_rigged` 全部 clip 在
**0.0072–0.0175**。截图里的直接证据：脚底**没有接触阴影**（阴影只落在身后地面），
且两只靴子的整个鞋底都看得全——真人站在地面上不可能同时出现这两点。

修法：有根平移轨道的四段改该轨道的每个采样点；手作三段**没有**根平移轨道，
追加一条常量平移通道，让偏移随 clip 走。**静态根 `translation` 保持 1.05332 不动**——
它决定「没有 clip 驱动根平移」时（表现层 MANUAL 停帧）的姿势，按某个 clip 的量调小
会让停住的姿势沉进地面。

### 关键教训（照做可省一轮）

1. **「斜」和「浮空」是两件事，别用同一个量具回答。** `measure_glb_upright` 全绿不代表
   角色站得住。判「斜」必须先指明是**躯干相对骨盆**还是**骨盆相对双脚**——两轮反馈里
   这两个问题各出过一次。
2. **统计口径（如取 min）必须逐项复核。** 取跨 clip 最小值在构建报告里看起来是
   「一个数」，实际效果是「一个 clip 正确、其余全错」，而且逐 clip 量之前完全不可见。
3. **骨骼级读数 ≠ 顶点级读数。** 骨骼高度随脚部旋转变化：`run` 摆动腿脚尖下压、
   `idle_guarded` 双脚放平，两者都正确贴地时骨骼级差 0.10 m 而顶点级差 0。
   拿骨骼数字收紧「是否贴地」的判据会做出在资产正确时失败的测试。
4. **间歇性沙箱拒绝要紧凑重试、不要退避。** 实测：连续 30 次 mkdtemp 29 次成功；
   每次隔 1 秒则 0/10。**等待本身让它失败**，「退避重试」的通用直觉在这里是反的。
5. **改完 GLB 必须重跑 `godot --headless --path src --import`。** 否则测试读到上一版
   资产，表现为「判据太严」的假失败——被测对象和测量对象不是同一份数据。
6. **Godot 骨骼名用下划线**（`mixamorig_LeftToeBase`）：glTF 导入会规范掉冒号，写冒号时
   `find_bone` 返回 −1、采样整段跳过、最低值恒 0，判据「全绿」但什么都没量。
   `get_bone_global_pose()` 返回 **Skeleton3D 局部**坐标（本骨架节点带 0.01 缩放与
   +1.05332 Y 偏移），必须乘 `skeleton.global_transform` 才是世界高度。
7. **CameraRig 独占写相机。** 想在 playtest 里挪机位必须走 `rig.set_zoom_size()` 等
   公开 API，直接写 `Camera3D.position/size` 会被下一帧覆盖，拍出一张「看起来正常」
   其实没生效的图。
8. **`_process` 里调用协程不会等待它。** 截图脚本在 `_process` 里 `await` 会在协程恢复前
   `quit()`，报「失败 0」且没有任何文件。取当前 viewport 纹理（不 await）即可。

### 尚未完成 / 已知限制

- **骨盆前移 0.154 m 未修**（最自然的下一步，但需要先定目标值）：唯一的可疑残余。
  两条路：给骨架再加一个人物作对照基线，或使用者目视确认「理想站姿」后把目标值交给
