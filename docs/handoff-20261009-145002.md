### 一、仓库体积 8.6 GB

- `.git/objects` 共 4856 个松散对象，8.6 GB；`git count-objects -vH` 显示 `packs: 0`，从未打包。本机没有安装 `git-lfs`，仓库没有 `.gitattributes`。
- **贴图重复不是体积来源。** `src/game/actors/swordsman/models/` 下四个动作版本（`aligned_motion_20260927`、`balanced_motion_20261006`、`20261008`、`20261008_swing`）各有三张贴图，md5 两两相同。Git 按内容寻址，相同文件只存一个 blob，所以工作树里四份，仓库里只有一份。`docs/art` 里大于 5 MB 的 PNG 同理。
- **真正的增长来源**是每个版本新增的大二进制文件，彼此内容不同，无法去重：
  - 每版约 60 MB 的 `.blend`（内嵌三张贴图）和约 60 MB 的 `.glb`（同样内嵌贴图）。
  - 历史上的 `cultivator_tripo_v9` 系列：`runtime*.glb` 七个版本各约 61–74 MB，`_imported.blend` 与 `.blend1` 各 83 MB，两个 Mixamo 上传 OBJ 各 62 MB。
  - 当前树里还跟踪着 5 个 Blender 自动备份 `.blend1`（`docs/art/ground_contact_course/`、`movement_garden/`、`state_transition_lab/`、`sword_flight_course/`）。是否算探索资产要先判断，不能直接删。
- 查最大 blob 的命令：
  `git rev-list --objects --all | git cat-file --batch-check='%(objecttype) %(objectsize) %(rest)' | awk '$1=="blob"' | sort -k2 -rn | head -30`
- **会阻止 gc 回收的引用**：`refs/codex/turn-diffs/checkpoints/...` 是 Codex 留下的检查点，指向一个包含 `tmp_probe/` 的快照，其中有 `work.glb`（74 MB）和 `leg_fixed.glb`（60 MB）。只要这个 ref 存在，这两个 blob 就不会被回收。删除这个 ref 前请先和使用者确认。
- **远端风险**：GitHub 拒收单个超过 100 MB 的文件，超过 50 MB 会警告。目前最大 83 MB，还能推送；但如果人物 `.blend` 或 GLB 继续变大，就会被拒。
