# 最早 3D 人物步行与现有候选的对照

用户反馈“走路像斜着”，并认为最早一版 3D 人物的走路尚可。本次沿当前仓库历史回查到 `240c23c`（2026-09-18）的初代低多边形修士，以及后续动作工作台的分件步态。这里只分析本实验室仓库，不从旧 `game-xiuxian-godot` 迁入任何东西。

## 最早一版实际怎么走

- 人物由 `tools/art/generate_movement_assets.py` 在 Blender 程序生成：原版 17 个独立网格、约 1.70 m 高，源文件保留在 `docs/art/movement_garden/cultivator.blend`。当时的 GLB **没有骨架、蒙皮或内嵌走路 clip**。运行路径 `cultivator.glb` 后来改为 refined 人物，不能用现今同名 GLB 反推当时的网格；[旧源台账](../../art/movement_garden/README.md)和 Git `240c23c` 才是历史依据。
- `cultivator_presentation.gd` 在 Godot `_ready()` 给 `Leg_L/R`、`Arm_Sleeve_L/R` 等独立网格建髋、肩枢轴。每帧读取真实水平速度；相位按 `delta × TAU × speed / stride_meters` 前进，腿围绕髋做相反方向的 `sin(phase) × 0.34 rad` 摆动，手臂反相做 `0.22 rad` 摆动。整体步行前倾只有 `0.05 rad`（约 2.9°），左右摇摆上限 `0.015 rad`（约 0.86°），另有约厘米级的轻微起伏。
- `SwordsmanMovement` 把按键投到相机地面基，角色根 `move_and_slide()` 执行真实位移；`Swordsman._face_aim()` 根据 aim 转动 Visual。早期先按局部 `-Z` 正面换算，后来查清模型实际按局部 `+Z` 解释，改由 `visual_yaw_for_aim()` 统一处理。**移动方向与视觉朝向必须同向**，动作脚本只摆局部肢体。
- 这是克制、易读的**程序化分件摆动**，不是完整步行动捕；没有脚掌 IK 或支撑期锁脚，近距离仍可能滑步。[早期动作工作台画面](../2026-09-18-motion-stage-run.png)中的人物很小，远景会弱化脚步细节。

## 本次“斜着”的两个来源

1. **对照场景朝向写反。** v5 GLB 的局部 `+Z` 是正面；旧对照场景固定 `-90°`，人物朝世界 `-X`，而场景沿 `+X` 移动。[旧错误截图](compare-loop-v2-candidate-2.png)不适合用于判断候选步态。已改用正式角色同一 `visual_yaw_for_aim(Vector3.RIGHT)` 换算；[修正后截图](compare-facing-v3-candidate-2.png)和实机验收均确认正面与位移点积 `1.0000`。
2. **CMU 候选上身仍有后仰。** 导出的 GLB 按整段动画取髋到头平均连线，相对铅垂的角度约 `8.01°`；同一骨架的现役手作 `walk` 为 `2.45°`。这是局部姿态问题，朝向修正不能消掉。CMU 的骨盆相对双脚平均水平偏移约 `0.077 m`，现役手作为 `0.128 m`，说明“脚下重心”和“上身直立”须分别看；这些均为骨骼位置代理，鞋底接触应看蒙皮网格测量。旧版分件步态整体 pitch 上限约 2.9°，因此更显平稳。

## 下一步技术判断

保留早期实现的三个原则：**视觉正面跟随实际位移、上身接近直立、摆臂克制**。当前人物是一个蒙皮网格，不能把最早的分件枢轴脚本直接挂上去；要借用其观感，应在**新候选**里约束 CMU 上身/肩臂并逐帧复测步幅与贴地，或另做本骨架上的轻量程序步态。现有 v5 CMU 不应因“比手作更自然”的早期结论被直接提为正式 walk，需先解决约 8° 的上身倾角并让用户连续观看。
