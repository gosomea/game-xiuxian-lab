入口：实验目录 →「剑法战斗」→ 剑法工作台。六按钮 / C 换招；新增三招按住左键凝聚、松开释放；R 重置，F 御剑，H 详情，右键拖动与滚轮调整镜头。「自动取景」可重新开启法术包络取景。

## 交付与判据

| 探索 | 实际动作流程 | 运动与画面判断 |
|---|---|---|
| 天轮剑阵 | 36剑螺旋入双轮 → 短暂转剑 → 六剑分组齐射 → 接地消散 | 内12外24，完整竖轮；剑身先转向再沿加速弧线飞行。金轮、青剑、尾迹分层可辨。快点也形成完整内轮。 |
| 巨剑镇落 | 凝形 → 锁点悬停上提 → 加速镇落 → 一次震击 → 残影收势 | 5.6米完整剑形与高冠环、地面符环同时可见；前缓后快的下落、单次顿帧和扩散冲击建立重量感。高台快速释放也完整接地。 |
| 天降剑雨 | 选区 → 高空聚剑 → 悬停 → 三批错峰下降 → 剑尖接地 → 散阵 | 24剑逐把显形，三批同时存在悬停、下落和接地；连续尾带与小冲击环清楚标记节奏，法环不遮掉落点。 |

主 Agent 已查看真实窗口的逐阶段画面与连续截图序列，检查人物收势、剑形、剑尖、法阵、轨迹、冲击和取景。视觉判断是三招拥有不同轮廓与节奏、施法和收尾可读、剑运动连续；这是本轮对「帅气」的实施判断，使用者仍可继续调整个人偏好。

连续朝向采用上一帧剑身的最小转角延续，避免近竖直方向参考轴切换造成突然翻滚；不以旋转滞后来掩盖剑尖误差。角色使用现役骨架与程序姿势，抬臂、下压和放下有平滑过渡及轻微屈肘。现役骨架没有手指骨，本轮无法生成可辨的掐诀手型。

## 实际验证

- 正式 integration：Godot 4.6 import、中央运行时 **2808通过 / 0失败**、Tier 0 与 **33/33负向控制**；三项 stderr 都为空。
- 快速组合：**142通过 / 0失败**，含跨竖直连续剑身、真实高台/侧面、释放归属、后台完成、蓄势取消、失焦、R 清账、御剑与本命剑阻塞。
- 旧三招真实窗口：**24通过 / 0失败**；剑气、飞剑去回、旧扇阵、御剑剑气及顿帧释放正常，截图保留在 `legacy-window/`。
- 新三招真实窗口：最终数值与30项流程检查在 `acceptance.json`；保存1280×800与960×600逐帧样本、高台快速巨剑和全部截图。检查单次剑运动无超过2米跳变、飞行剑尖与轨迹切线一致、阶段完整、真实命中、R和输入入口。
- 主 Agent 的最终语义评审绑定计划 revision、attempt、subject 与本报告/数据文件，随计划 validation 导出保存。三个原生子 Agent 分别负责独立分支，另做一次只读集成审查；最终窗口由主 Agent 执行与检查。

首轮旧命中测试暴露冷却未推进、首轮960窗口输入模拟漏做 stretch 转换；均已修正并重跑。独立审查发现同帧释放被切招清掉、旧招释放误用于新招、边墙和平台侧面误作地面四项问题；通过按招式归属交付释放及地面层/法线筛选解决。后续复核无新的阻塞。
