# 《Kenshi》玩法与视觉参考深度调研

调研日期：2026-09-19

对象：Lo-Fi Games《Kenshi》（用户原文 “kenish” 按《Kenshi》理解）

用途：为 `game-xiuxian-lab` 的独立模块与组合实验提供参考，不替项目决定最终核心循环、死亡规则、经济、世界规模或最终美术。

## 阅读约定

- **[事实]**：来自开发商页面、开发者采访、官方开发日志或成品评测。
- **[分析]**：由多项事实归纳出的设计结构，不等于开发者原话。
- **[建议]**：针对本项目的可验证方向，尚未成为项目决策。
- **[风险]**：参考时容易连同优点一起带入的成本或缺陷。

这份文档研究的是“为什么这些系统与画面共同成立”，不是功能抄单。所有建议都遵守 [模块实验室的探索约定](../../design/pillars.md)：先做可独立运行的局部实验，允许组合，但不提前收口成一款完整游戏。

## 0. 结论先行

《Kenshi》最值得本项目借鉴的不是“开放世界很大”，而是以下六个设计关系：

1. **失败是状态变化，不总是流程终止。** 战败后可能受伤、昏迷、被俘、被奴役、失去队友或肢体；这些结果继续产生救援、逃亡、治疗和装备需求。失败因此能生成下一段玩法，而不只是读档。[事实]
2. **成长与行为直接对应。** 角色做什么就练什么；挨打和重新站起来也能转化为韧性。成长不是独立菜单，而是经历留下的可见痕迹。[事实]
3. **世界压力主动找玩家。** 派系、法律、巡逻、野兽、袭击、税收和环境危险都有自己的规则。玩家不接任务，局势仍可能撞上来。[事实]
4. **多个朴素系统通过共享状态耦合。** 伤势影响移动与战斗；身份影响执法；据点位置影响资源、税收与袭击；队员分工影响能否从失败中恢复。[分析]
5. **高位镜头同时服务角色、地形和群体决策。** 它让玩家既能看见个人遭遇，又能拉远阅读路线、聚落和荒野尺度；这比单纯模仿“斜俯视角度”更重要。[分析]
6. **画面靠强方向而非高保真成立。** “浪人 + 荒原幸存者 + 拼装技术 + 异星生态”的 sword-punk 语法贯穿人物、建筑、地貌和伤残系统；低饱和大地、远景剪影、稀疏地标和巨大留白强化了孤独、危险与尺度。[事实 + 分析]

对本项目最直接的启发是：

- 玩法上优先验证“**遭遇—状态变化—恢复/应对—留下成长痕迹**”，而不是先造庞大的任务链。
- 视觉上优先验证“**近景材质、中景构图、远景剪影**”以及地点之间的形状/色温差异，而不是追求《Kenshi》的荒漠色或废土表皮。
- 2.5D 上优先验证“**高位镜头的多尺度可读性**”：角色动作、可走路径、危险来源、地标与远景需要在同一套构图层级中共存。
- 不照搬《Kenshi》的漫长空跑、刻意晦涩、密集小字 UI、重复劳动、路径寻找负担和技术粗糙感。

## 1. 先纠正一个概念：《Kenshi》不是严格意义的 2.5D

《Kenshi》运行在完整 3D 世界中，镜头可以平移、旋转和缩放；角色移动、建筑内外、地形高差与战斗也都发生在三维空间。PC Gamer 对成品操作的描述是：鼠标下达移动命令，WASD 控制镜头，战斗自动执行但可调防御姿态、远程行为和队形。[事实]

因此它不是“二维逻辑 + 三维表现”或“固定等距投影”意义上的 2.5D。它与本项目相关的地方，是玩家大部分时间通过**斜俯视、高位、可拉远的策略构图**阅读完整 3D 世界。

可以借鉴的层是：

| 可借鉴 | 不应误认 |
|---|---|
| 斜俯视下的轮廓、路径、遮挡与地标组织 | 固定相机或正交投影本身 |
| 从单人近景到小队/聚落远景的尺度切换 | 必须做 RTS 式鼠标点地移动 |
| 角色状态与世界空间同时可见 | 必须做无缝超大地图 |
| 大体块、低频地形、远景剪影 | 必须使用废土、灰黄或低精度模型 |
| 镜头距离变化时信息密度分级 | 把所有 UI 和单位信息常驻屏幕 |

本项目已经有 `fixed_follow`、`quarter_turn`、`orbit`、`overview` 四种 CameraRig 模式。《Kenshi》提供的参考不应变成“再加一种 Kenshi 镜头”，而应转化为同一场景在近/中/远三个阅读距离上的验收问题。

## 2. 产品定位与体验承诺

Lo-Fi Games 将《Kenshi》定义为自由漫游、队伍制、开放式沙盒 RPG；它混合 RPG、队伍控制与城市建设，不依赖线性故事。开发者明确强调玩家不是天选者，初期几乎所有人都更强，世界不会随玩家等级缩放。[事实]

官方列出的主要活动包括：

- 单人或小队探索；
- 训练不同技能；
- 交易、偷窃、行医、工程、锻造等职业；
- 招募与分队；
- 建筑、研究、生产和据点经营；
- 与派系结盟或开战；
- 受伤、失血、昏迷、被俘、越狱、救援和义肢替换；
- 在没有传统主线任务的情况下改变世界状态。[事实]

### 2.1 它卖的不是“无限自由”，而是“自由承担后果”

表面宣传是“你可以成为任何人”，真正支撑自由的结构却是：

```text
选择身份/行为
    ↓
世界按统一规则回应
    ↓
角色、关系、身体、资产或地点发生持久变化
    ↓
玩家为新状态自定下一个目标
```

若缺少第二、三步，“自由”只会变成无事可做。《Kenshi》的关键不是活动数量，而是活动共享伤势、金钱、物资、技能、通缉、派系和地点等状态，使一种活动的结果可以成为另一种活动的起点。[分析]

### 2.2 玩家不是世界中心，但玩家仍能留下痕迹

官方 FAQ 强调：NPC 与玩家使用同一套能力与技能逻辑，没有专门为玩家准备的无敌人物；世界不会同步升级。玩家初期弱小，但后期可以建造势力、保护地点、挑战政权或改变派系格局。[事实]

这里形成一组很重要的张力：

- **地位平等**：玩家不是规则例外。
- **能力不平等**：开局大多数实体都比玩家强。
- **长期可改变**：通过经历、组织与资源，玩家最终能改变局部乃至世界。

这比“开局弱、后期强”的普通数值曲线更有力，因为玩家的强大是相对于一个先存在、不会迁就自己的世界被证明出来的。[分析]

## 3. 玩法循环不是一个，而是互相嵌套的五层循环

### 3.1 秒到分钟：观察—下令—反馈

```text
观察单位/地形/威胁
→ 选择角色或小队
→ 移动、交互、姿态或战斗命令
→ 自动执行与实时反馈
→ 暂停/改令/撤退
```

战斗并非强调逐帧输入，而是强调开战前判断、角色配置、位置、数量、姿态以及是否撤退。官方 FAQ 说明游戏可随时暂停下令；PC Gamer 也指出战斗大体自动，但玩家能调整防御、远程与队形。[事实]

### 3.2 分钟到小时：遭遇—损失—恢复

```text
旅行/工作
→ 被袭击或卷入事件
→ 战斗、逃跑、藏匿、投降或利用第三方
→ 受伤/昏迷/被俘/分散
→ 包扎、搬运、营救、越狱、休养
→ 带着新技能、关系和故事继续
```

这是《Kenshi》最有辨识度的循环。开发者明确表示，很多战败不会直接死亡，失败者还可能获得比胜利更多的经验；代价是伤势、恢复时间与后续风险。[事实]

### 3.3 小时级：谋生—积累—扩展选项

```text
采集/拾荒/交易/偷窃/赏金
→ 获得钱与物资
→ 装备、招募、购买房产、研究
→ 可以进入更危险地区或承担更大目标
```

这层不是传统“接任务—交任务”，而是资源让玩家获得新的承压方式。雇佣保镖、在城里买房、建立研究与生产，都能改变早期只能逃跑的处境。[事实]

### 3.4 组织级：分工—自动化—守护系统

```text
招募成员
→ 分配劳动/医疗/战斗/制造职责
→ 建立自动工作链
→ 产出与防御形成组织能力
→ 世界用税收、袭击、法律和资源约束反向施压
```

PC Gamer 记录了采矿、农业、建造等长任务队列，以及据点面临的野兽、强盗、税收和地区法律。[事实] 这使“基地建设”不是脱离世界的装饰玩法，而是把玩家从个人风险升级到组织风险。

### 3.5 长期：自定目标—改变世界—重写身份

玩家可能从拾荒者变成商人，从奴隶变成逃犯，从独行者变成队长，从临时营地变成势力据点。目标不是系统预先列成主线，而是由现状与玩家价值取向共同生成。[分析]

## 4. 关键系统拆解

### 4.1 行为即成长：把数值绑定到经历

《Kenshi》没有让世界跟随玩家升级。技能通过对应行为提高；更强对手与更艰难处境可能带来更高成长，韧性尤其与受伤、被打倒和重新站起有关。[事实]

其设计价值有三层：

1. **可解释**：跑得多所以跑得快，负重多所以力量增长，受挫后更坚韧。
2. **可叙事**：数值不是抽象点数，而是“这个人经历过什么”的记录。
3. **会改变玩家决策**：弱势战斗不再只有“值不值得赢”，还要考虑“能否活着承受”。

但它也产生明显问题：玩家可能机械负重跑圈、故意挨打或寻找最高效的训练漏洞。[风险]

**对本项目的转译**不是照搬“刷什么涨什么”，而是测试：一次移动、御剑、切磋或交互后，角色是否留下**玩家看得懂、与行为因果一致**的变化。

### 4.2 失败连续体：把二元胜负拆成多个可恢复状态

《Kenshi》的身体不是单一生命值。官方资料描述了局部伤势、失血、跛行、爬行、昏迷、饥饿与义肢；不同伤势会改变移动、持械与恢复方式。[事实]

可抽象成：

```text
健康
→ 轻伤（效率下降）
→ 重伤（行动受限）
→ 昏迷/倒地（依赖队友或环境）
→ 被俘/搬走/遗弃（身份与空间变化）
→ 获救/逃脱/长期改变
→ 死亡（少数不可逆终点）
```

这里最重要的不是残酷表现，而是**状态间仍有操作空间**：队友能包扎、搬运、营救；角色可能苏醒；敌人可能不补刀而是俘虏；受伤可能成为更换义肢的长期转折。[分析]

对修仙题材，可将身体伤残替换或扩展为更符合项目气质的状态：气息紊乱、经脉受阻、法器受损、御剑失稳、神识暴露、临时境界跌落等。关键仍是“失败产生新问题”，不是照搬血腥或断肢。[建议]

### 4.3 角色不是兵种：队伍规模与个体爱护并存

官方 FAQ 明确区分《Kenshi》与生产无名单位的传统 RTS：每个角色都有姓名、技能、装备和个性，可以组成一个或多个小队；官方旧 FAQ 认为约 4–15 人是比较合适的规模。[事实]

这种结构同时制造：

- RTS 的分工、编队和多点管理；
- RPG 的个人成长与装备；
- 失去一个成员时真实的组织缺口；
- 搬运伤员、秘密留守医师等“关系型战术”。

开发者在采访中解释，严重身体后果会让玩家更想救助角色，从而加强依恋。[事实]

本项目当前以单角色移动实验为主，因此不应立即扩成队伍系统。更小的验证单位可以是“主角 + 1 个同行 NPC”：当一方倒下时，另一方能否救援、撤离或继续任务，已经足够检验关系型失败是否有趣。[建议]

### 4.4 世界事件：不是任务触发器，而是系统相撞

官方 FAQ 将世界描述为由派系、宗教、军队、罪犯、执法者、野生动物与环境组成的 AI 生态；它们各自追求目标，冲突时形成事件，玩家再决定是否介入。[事实]

官方袭击开发日志还描述过来自实际营地或城镇人口的动态袭击；攻击者可能抢掠、奴役、勒索、占领或摧毁，玩家也可攻击源头、削弱该势力。[事实]

设计结构是：

```text
实体有目标 + 空间中移动 + 条件相遇
→ 冲突/交易/执法/求助
→ 局部状态改变
→ 后续巡逻、关系、资源与地点状态改变
```

它比“随机弹一个事件窗口”更有说服力，因为事件有来源、有去向，玩家能理解甚至提前干预。[分析]

### 4.5 派系与法律：地点本身就是规则集

不同地区不是只换怪物和贴图，还会改变：

- 谁掌权；
- 哪些身份、种族、装备或行为被容忍；
- 进入城镇是否受检查；
- 据点会面对税收、祈祷、勒索或袭击；
- 哪些贸易与资源更安全；
- 谁会在冲突中帮助或追捕玩家。[事实]

这使地图地点具有“规则含义”。玩家看到城门、制服和建筑风格时，应该开始预测社会风险，而不只是欣赏景观。[分析]

### 4.6 据点：把便利转换成责任

据点提供生产、研究、储存与防御，但也把玩家暴露给袭击、税收和区域政治。力量增长没有消除压力，而是把压力从“我会不会被打倒”升级为“我能否保护已经建立的东西”。[事实 + 分析]

这是一种比简单提高敌人数值更自然的难度升级：

| 阶段 | 玩家拥有 | 新责任 |
|---|---|---|
| 独行 | 自己与随身物品 | 生存、撤退 |
| 小队 | 多个有价值的成员 | 救援、补给、分工 |
| 房产/作坊 | 固定资产与生产 | 维护、供应、安全 |
| 据点 | 人口、产业、领土 | 防御、外交、连续运营 |

### 4.7 信息不完全与环境叙事

《Kenshi》不急于解释世界历史。遗迹、机械残骸、异常生态、派系偏见和地域危险先作为事实存在，玩家从探索与冲突中拼接理解。[分析]

这种叙事方式的优势是世界显得早于玩家存在；风险是玩家可能不知道可做什么、为什么被惩罚。PC Gamer 将成品形容为庞大、冷漠且晦涩，并指出前期慢、管理繁琐、UI 负担重。[事实]

因此本项目若借“留白”，必须把**操作因果**说清楚：可以不解释上古真相，但不能让玩家不知道自己为何受伤、为何被拒绝进入、哪个行为改变了关系。[建议]

## 5. MDA：机制如何生成《Kenshi》的核心感受

| Mechanics 机制 | Dynamics 涌现行为 | Aesthetics 玩家感受 |
|---|---|---|
| 世界不随玩家升级 | 绕路、侦察、借助守卫、雇佣保镖 | 世界真实地强于我；谨慎 |
| 行为对应成长 | 玩家主动寻找可承受的练习风险 | 从无名者成长为能者的成就 |
| 多阶段伤势与昏迷 | 战后抢救、搬运、追踪俘虏 | 紧张、爱护、失而复得 |
| 个体角色 + 小队控制 | 留守医师、分队、职责互补 | 组织感与同伴故事 |
| 派系、法律、巡逻 | 借势、误入冲突、结仇、救援 | 世界不围着玩家转 |
| 自动工作链 + 据点 | 生产稳定后出现防御与外交压力 | 从苟活到经营的责任升级 |
| 稀疏引导 + 巨大空间 | 自定目标、旅行、偶发遭遇 | 孤独、自由、发现感 |
| 持久世界状态 | 打倒领袖后城镇或刷出状态改变 | 行动有长期分量 |

《Kenshi》的核心审美体验可以概括为：

> **我不是被剧本宣布为重要的人；我因为活下来、照顾过谁、失去过什么、建成过什么，逐渐变得重要。**

这是本调研最值得保留的设计内核。[分析]

## 6. 视觉与画风拆解

### 6.1 “Sword-punk” 是世界规则，不只是贴图风格

Chris Hunt 将其描述为：绝望游荡的浪人、荒原幸存者、暴力住民与拼装技术的组合，带有蒸汽朋克—武士混合感，但不是日本背景；它有自己的种族、动植物和历史，同时出现剑、忍者、怪物、末日式机械义肢与建筑。[事实]

其视觉语法可拆成：

| 层 | 《Kenshi》的做法 | 产生的意义 |
|---|---|---|
| 人物 | 浪人、忍者、布衣、盔甲、伤残、义肢 | 身份由生存方式和经历塑造 |
| 道具 | 大型刀剑、拼装机械、面罩、粗粝容器 | 技术可用但不洁净、不稳定 |
| 建筑 | 围墙、塔楼、棚屋、残骸、厚重防御体块 | 聚落首先是危险世界里的生存装置 |
| 地貌 | 荒漠、盐地、沼泽、焦土、奇异岩体 | 地区本身就是威胁与历史 |
| 生物 | 熟悉骨架 + 异常比例/轮廓 | 世界陌生但仍可快速辨认危险 |
| 色彩 | 低饱和大地色为基底，生物群系有局部色温差 | 统一荒凉感，同时保留地区记忆点 |

**可借的是“造型服从世界处境”**，不是把修仙场景做成废土。[建议]

### 6.2 大地貌先于小装饰

官方资料称世界为约 870 平方公里的无缝地图；开发日志也承认填充巨大土地很困难，因此除城镇与遗迹外，还要靠地表纹理、植物、天气、光照和小型特征维持兴趣。[事实]

画面常见的层级是：

1. **远景**：巨大山脊、岩柱、遗迹轮廓或天空现象，负责方向与陌生感。
2. **中景**：道路、聚落、坡谷、植被带，负责可达性和危险预判。
3. **近景**：人物、伤势、装备、交互物，负责即时操作。

这种层级非常适合本项目既定的“近景材质、中景构图、远景剪影”。《Kenshi》证明远景不只是背景；它承担导航、地区身份和情绪预告。[分析]

### 6.3 留白不是空，而是让风险、距离与地标可见

《Kenshi》大量使用低频地形和稀疏分布：角色在开阔地上显得很小，远处队伍和地标因此特别醒目。留白同时提供：

- 世界尺度；
- 旅行脆弱感；
- 敌我轮廓的提前暴露；
- 让一个城门、一棵怪树、一组遗迹成为记忆点的空间。

但留白若没有路线选择、地标、遭遇概率或时间成本控制，就会退化为漫长空跑。PC Gamer 明确批评了移动、成长与生产耗时过长造成的拖沓。[事实 + 风险]

### 6.4 生物群系需要同时改变画面与玩法

官方开发日志反复把光照、天气、植被、地表、城镇、种族、偷窃内容和环境危害一起讨论，而不是只换地表颜色。[事实]

一个强生物群系至少应有四个共同变化：

| 维度 | 问题 |
|---|---|
| 轮廓 | 远处一眼看见什么形状？山脊、竹海、残塔还是云海？ |
| 色光 | 主色、雾色、天空和高光怎样提前传达气候/情绪？ |
| 通行 | 哪些地方可走、需跳、需御剑、会减速或暴露？ |
| 社会/生态 | 谁在这里生活？他们的建筑、资源、危险与规则为何成立？ |

如果只改变第一、二项，它是换皮；四项协同，才会形成地点记忆。[分析]

### 6.5 建筑首先表达派系功能和态度

Lo-Fi 的开发日志描述过：防御墙与城门沿用派系既有建筑语言，通过厚重体块、简单几何、更多金属和可选防御模块形成军事感；旧日志也强调多层建筑与无缝内外空间。[事实]

这说明建筑可读性来自：

- 谁建的；
- 用来防什么；
- 允许谁进入；
- 当地有什么材料与技术；
- 玩家能在其中做什么。

对本项目，宗门建筑不应只区分“瓦片颜色”，而可通过山门开合、台阶权力距离、练功区公开程度、御剑落点、访客路径和禁区边界表达门派态度。[建议]

### 6.6 人物与动作：远看先读状态，近看再读细节

高位镜头下，角色面部不是主要信息载体。玩家首先需要读到：

- 是走、跑、蹲伏、战斗还是倒地；
- 是否跛行、爬行、负重或搬运同伴；
- 手持武器类别和攻击方向；
- 属于哪一队或哪个派系；
- 是否正在被追捕、包扎或工作。

《Kenshi》的局部伤势之所以有效，是因为状态直接改变姿态与行动，不只改变 HUD 数字。[分析]

这与本项目人物动作工作台的优先级一致：剪影可读性、接触关系和状态转换应先于脸部与服装微细节。

### 6.7 色彩与材质：一致的脏旧逻辑，而非统一一个颜色

《Kenshi》的地点色彩并不都相同，但大多共享风化、尘土、褪色、氧化和粗糙表面，使不同区域仍像同一世界。局部鲜色通常属于环境危险、特殊生态或派系识别。[分析]

本项目的“青玉暖木 + 青灰岩 + 深松绿 + 灰米地面 + 低饱和青蓝天空”可以采用同样的统一方法，但把“脏旧”翻译为：

- 山石的水蚀与苔痕；
- 木构的使用痕迹和修补；
- 青玉构件的细微色差与包浆；
- 衣摆、剑鞘和行囊留下的旅途痕迹；
- 不同海拔的雾、湿度与植被变化。

不要直接引入黄沙滤镜、废铁、机械义肢或末日破败；那是《Kenshi》的题材表达，不是其视觉方法。[建议]

### 6.8 UI 是反例与提醒

PC Gamer 认为《Kenshi》的机制与 UI 有老式 MMO 的晦涩感，队伍扩大后库存转移和组织管理变得繁琐；日本采访还记录过字体过细、玩家依赖粗体字体 MOD 的反馈。[事实]

本项目应借它的**世界可读性**，不借它的界面负担：

- 世界中的状态尽量先由姿态、轮廓、颜色和空间关系表达；
- HUD 只补充无法可靠看出的精确信息；
- 小屏和远景下优先显示“发生了什么”，详细数值按需展开；
- 中文字体粗细、字号、背景对比必须实机验证。

## 7. 与本项目八个模块的对应关系

下表是研究结论到实验问题的映射，不是实施排期。

| 本项目模块 | 最值得借的原则 | 可独立验证的问题 | 不要顺手扩大 |
|---|---|---|---|
| 地图探索 `world_map` | 地点同时改变轮廓、通行、生态与社会规则 | 三个相邻区域能否只看远景和地表就预判路线与风险？ | 无缝 870 km² 世界、全套世界生成 |
| 角色移动 `character_movement` | 近/中/远多尺度阅读；伤势改变动作 | 镜头拉远后，步行、跳跃、御剑、负重/受阻仍能从剪影辨认吗？ | 鼠标 RTS 控制、大队伍寻路 |
| 剑法战斗 `sword_combat` | 战败不是立即结束；战后状态仍可操作 | 一次败北能否进入可撤离、救援、调息或追捕状态？ | 血腥断肢、完整战争模拟 |
| 小镇交流 `town_dialogue` | 地点法律和派系态度在进入前可预判 | 山门守卫、服饰、提示与对话能否让玩家理解“谁能进、为何被拦”？ | 大量任务树、完整政权剧情 |
| 人物成长 `character_growth` | 行为与成长因果一致 | 御剑、切磋、受挫、疗伤各自留下什么可见成长？玩家能否解释变化来源？ | 可被机械刷取的几十项技能 |
| 人物交互 `character_interaction` | 行为改变关系、访问权与后续援助 | 赠送/交易/切磋后的关系变化，能否在下一次真实行为中体现？ | 全派系外交与声望经济 |
| NPC 生活 `npc_life` | 世界事件由日程、目标和冲突相遇生成 | 两个 NPC 各有目标时，冲突是否产生可理解事件，并能在被打断后恢复？ | 全地图离屏精确模拟 |
| 背包物品 `inventory` | 物品服务角色状态与选择，不只是收集 | 药、法器、负重与装备如何改变移动、恢复或社会识别？ | 十人背包搬运、海量格子整理 |

## 8. 建议的六个低成本实验

以下按“先得到信息，再扩大投入”排序。它们都可以独立运行，不要求串成完整游戏。

### R0：Kenshi 式多尺度构图对照板

**目的**：验证《Kenshi》真正相关的 2.5D 视觉方法，而不是模仿配色。

同一块 80–120 m 场地做三种镜头证据：

1. 近景：人物动作、足—地/足—剑接触、衣摆和装备类别可读；
2. 中景：路线、台阶、落点、危险方向与 NPC 分组可读；
3. 远景：山体/宗门剪影、可达区域和地点身份可读。

对照变量只改：地标轮廓、地表带、植被聚散、雾与局部色温。不要同时新做玩法。

**通过问题**：隐藏 HUD 后，首次观看者能否指出“人在哪、能去哪、哪里危险、目标地标是哪一个”？

### R1：失败连续体小场

**目的**：检验“失败产生下一步”是否适合修仙题材。

只放一名玩家、一名同行 NPC、一个强敌和一个安全边界。战败后不立刻重置，而进入候选状态：

- 气息紊乱：移动/御剑暂时受限；
- 倒地但可被拖离；
- 同行者可救援或被俘；
- 法器受损，需要回到特定地点修复；
- 脱离后通过调息恢复。

**通过问题**：玩家是否能在 5 秒内理解自己仍能做什么？失败后的新目标是否自然，而非系统强塞任务？

### R2：世界压力主动到访

**目的**：验证“麻烦来找你”，但不做完整派系模拟。

做一个山门/驿站场景，只有三类移动实体：巡逻守卫、旅行商队、追踪者。各有来源、目标和离场点；相遇条件触发检查、交易或追捕。

**通过问题**：事件是否看得出“从哪里来、为何发生、之后去哪”？玩家不介入时事件能否自行收束？

### R3：三生境地点语法

**目的**：验证地图地点能否同时在视觉和规则上区分。

用同一套资产变体建立：

- 云松山门：开阔视线、守序、进入检查；
- 竹雾谷：遮挡强、近路多、感知困难；
- 裂岩剑冢：高差强、御剑捷径、法器风险。

每处只需要一个轮廓母题、一条通行规则、一个生活实体和一种局部风险。

**通过问题**：去掉地点名后，玩家能否根据画面预测最合适的移动方式与风险？

### R4：行为留下成长痕迹

**目的**：验证成长模块的因果透明度。

选三种行为，不做完整数值树：步行/御剑、切磋、疗伤。每种行为只改变一个主要维度，并同时提供：

- 动作或节奏变化；
- 一条简洁状态说明；
- 前后可重放对照。

**通过问题**：不看公式时，玩家能否说出“为什么变强、强在哪里”？

### R5：关系变化必须在行为中兑现

**目的**：避免关系值只存在于菜单。

同一 NPC 提供中立、信任、敌视三个状态，变化后至少改变一项真实行为：接近距离、是否开门、是否疗伤、交易条件、是否通报守卫。

**通过问题**：不打开关系面板，玩家能否从 NPC 下一次行动中看出关系改变？

## 9. 一个适合后续组合验证的“微型 Kenshi 结构”

如果上述独立实验各自成立，可把它们组合成一个 10–15 分钟的**山门驿站一日**，但它仍不是最终核心循环：

```text
到达驿站
→ 从地貌/守卫/人流读出当地规则
→ 选择交易、求助、绕行或进入禁区
→ 巡逻与追踪者发生系统性相遇
→ 玩家介入或回避
→ 产生伤势、关系、物品或通行状态变化
→ 通过疗伤、交涉、救援或御剑撤离收束
```

它一次只验证四件事：地点规则是否可读、事件是否有来源、失败后是否仍有选择、结果是否留下痕迹。它不需要主线、经济闭环、建城、全派系或无缝地图。[建议]

## 10. 明确不照搬的部分

### 10.1 不照搬大地图与长旅行

《Kenshi》的尺度制造孤独和旅途感，也制造大量等待、寻路与性能成本。模块实验室应先用紧凑场景验证“距离有没有意义”，而不是用公里数证明世界大。[风险]

### 10.2 不照搬靠重复劳动训练

行为成长很直观，但重复负重、挨打和生产容易变成最优刷法。应优先奖励“完成有风险、有判断的行为”，并设收益衰减或里程碑，而不是奖励无意义次数。[风险]

### 10.3 不照搬信息晦涩

世界背景可以留白，操作后果不能含糊。违法、敌意、伤势恶化、关系变化、御剑限制等应给出明确因果反馈。[风险]

### 10.4 不照搬多系统同时上线

《Kenshi》的深度来自十多年叠加。一次实现战斗、医疗、派系、经济、AI 日程、建城与世界状态，会让本项目失去模块实验的可验证性。[风险]

### 10.5 不照搬题材表皮

废土、武士、义肢、奴隶制、食人族、黄沙和粗糙 UI 都不是可迁移的设计原则。项目必须保持自己的青玉暖木、修仙山居与水墨远景方向，也不得复制《Kenshi》的资产、角色、建筑或专有视觉设计。[边界]

### 10.6 不把技术缺陷浪漫化成风格

《Kenshi》的辨识度能跨过技术粗糙，但路径寻找、性能、交互繁琐和字体问题仍是真问题。我们可接受探索资产尚不精致，不能把不可读、卡顿或难操作解释为“有味道”。[风险]

## 12. 对当前青玉纸白方向的具体启发

《Kenshi》不应改变项目已经确立的视觉方向，但能补足其“世界如何通过画面运作”的部分：

| 当前方向 | 从《Kenshi》吸收的方法 | 转译后的执行原则 |
|---|---|---|
| 国风动画化、精致低模 | 远距离首先读体块和状态 | 人物、飞剑、松、亭、山门先过剪影，再加材质 |
| 青玉暖木色卡 | 统一风化逻辑维持世界一致 | 青玉有包浆色差，暖木有修补与使用痕迹，不做塑料新件 |
| 水墨意象远景 | 远景承担导航与情绪 | 每个区域至少一个可命名的大轮廓，不只放通用远山 |
| 光影与雾形成层次 | 生物群系同时改变规则 | 雾不仅好看，还影响视距、路线与遭遇预判 |
| 角色与飞剑细轮廓 | 高位镜头优先显示状态 | 轮廓服务步行/跳跃/御剑/受阻区分，不做全场描边 |
| 建筑分层清楚 | 建筑表达派系功能 | 山门、台基、落剑点、守卫位置共同表达开放或排斥 |
| 植被成组有聚散 | 留白帮助地标与风险可见 | 植被带用于导路、遮挡或分区，不均匀撒满 |

一句话概括：**保留我们的颜色、材质与修仙造型，借《Kenshi》的空间语法、状态可视化和世界因果。**

## 13. 研究限制

- 本轮没有实际游玩《Kenshi》，结论来自官方页面、开发日志、开发者采访、官方截图页和成品评测；具体数值与版本细节不是本文重点。
- 官方 FAQ 包含开发中时期的历史表述，其中“断肢未来再加入”等段落已被成品功能取代；本文只用它说明设计意图，并用当前官方 About 页交叉确认成品伤势/义肢功能。
- “近/中/远构图”“留白功能”“多系统共享状态”等属于分析归纳，不是开发者逐字陈述。
- 对本项目的实验建议尚未经过使用者试玩，不构成美术或玩法验收。
- 本文没有授权复制《Kenshi》的资产、世界设定、角色、派系、建筑造型、文本或专有视觉设计。
