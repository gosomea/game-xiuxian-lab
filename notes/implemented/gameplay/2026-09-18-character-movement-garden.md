# Note: 先探索角色移动与 Blender 场景呈现

Status: implemented

## 问题

使用者明确指出：首个场景可以先实现移动，但不应预设剑法与战斗规则；不接受主代理选择的简单范围攻击。探索场景也应有美观的 3D 呈现，模型尽量通过 Blender 生成。

## 决策

依据 2026-09-18 使用者的方向修正，保留移动、撤回未提交战斗实现，首个实验提供纯移动庭院。

- 首个实验只观察角色外形、屏幕相对 WASD 移动、转向、碰撞、镜头与空间尺度。角色按移动方向转向，停下保持朝向；鼠标不承担战斗瞄准，左键不触发攻击。
- 新入口为 `src/levels/experiments/character_movement/movement_garden.tscn`，美术采用纸白青绿基调的风格化修仙庭院：石板步道、矮石台、石灯、岩石与植物，有可绕行的空间。
- 使用本地 Blender 独立后台进程创建全新模型文件，不操作用户当前未保存的 .blend 会话。导出 GLB，保留可复现建模脚本、.blend 源文件与资产台账。Blender MCP 在当前工具列表未提供，CLI 为本轮执行路径。
- 角色为简化但轮廓完整的修士，有发髻、交领、衣袍、腰带、袖子、双脚；不装备剑。角色目前为静态网格，移动时仅转向，没有走路或骨骼动画；最终角色与动画风格仍待试玩。
- 角色 GLB 属于 `src/game/actors/swordsman/models/`；庭院 GLB 属于新实验场景目录并以场景名前缀命名。现有 SwordsmanMotionComponent 与移动能力保留，暂不为命名进行跨文件迁移，名字不构成战斗规则。
- Blender 原文件与生成说明放 `docs/art/movement_garden/`；生成脚本放 `tools/art/`，不属于门禁脚本。GLB 轴向、尺度、材质、网格数量通过 Blender 与 Godot 两端读回。
- 移除本次未提交的 practice_slash 包、词汇、测试、练剑场与截图；原提案迁入 rejected 保留否决原因。不迁移或读取旧修仙项目素材。
- 角色移动为 exploring 且只有一个有效入口；剑法恢复 planned、scene 为空，其他模块不变。目录、README、AGENTS 当前状态与实验记录同步。
- 验证移动能力测试、完整 Tier 0 门禁、纯移动场景的真实物理状态与截图。手感、美观的最终评价交使用者。

## 备选方案

- 继续修饰近身范围练剑场：违背本轮明确纠正，撤回。
- 保留挥剑入口但隐藏 UI：仍然预设未讨论的战斗设计，不采用。
- 继续只用引擎基本几何占位：无法满足使用者对探索阶段美观的要求，改为 Blender 模型。

## 后果

- 移动能力已有 17 项配对断言；当前运行时套件 87 项通过，场景输入/物理与目录回归另有取证，见[运行验收](../../../docs/playtest/2026-09-18-character-movement.md)。用户对手感与审美的评价仍待试玩，模块保持 exploring。
- 角色与庭院使用本次原创 Blender 程序建模，保留 .blend 源文件和 GLB；复现与限制见[美术说明](../../../docs/art/movement_garden/README.md)。这不等同于最终角色雕刻、骨骼绑定或成品动画。
- 碰撞使用四周边界与两个静态障碍代理；灯、竹、亭暂为装饰，无完整碰撞体。后续根据移动探索反馈继续调整。
- 旧[移动与剑法组合提案](../../rejected/gameplay/2026-09-17-movement-sword-experiment.md)被否决，剑法仍无场景入口，后续必须单独设计。
