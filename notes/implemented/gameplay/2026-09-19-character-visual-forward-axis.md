# Note: 角色视觉正面轴统一为局部 +Z

Status: implemented

## 问题

全部角色移动实验中，角色的物理位移与 `aim_direction` 正确，但人物视觉恒定反向：按 W
沿相机前方移动时，背部朝向行进方向。共享角色根 `Swordsman._face_aim()` 与动作预览
`MotionPreviewDisplay` 都把模型局部 `-Z` 当成正面；现役模型的实际导出约定则是局部 `+Z`
为正面。以 v7 为例，Blender 的 `-Y` 正面经 `export_yup=true` 导出后成为 Godot `+Z`。

## 决策

角色视觉正面轴统一登记为局部 `+Z`：

- 正式角色 yaw 使用 `atan2(aim.x, aim.z)`；
- 动作预览使用同一公式，并以 `Vector3(sin(yaw), 0, cos(yaw))` 表示可观察正面；
- 不修改物理移动、相机地面基、输入映射或 `aim_direction`，因为它们已经与实际位移同向；
- 不在每个模型子场景分别补 180°，避免新模型继续重复修正，也避免正式角色与动作预览分叉；
- 回归测试同时覆盖世界 `FORWARD(-Z)` 与 `RIGHT(+X)`，断言由 yaw 还原的局部 `+Z`
  正面与 aim 点积接近 1。

该变更作用于所有使用共享 `Swordsman` 的移动场景，以及动作工作台的独立预览。飞剑仍挂在
`Visual` 下并与角色共用 yaw；本轮不改变其局部装配偏移或飞行规则。

## 备选方案

1. 只把 v7 模型子节点旋转 180°——能修最新样板，但其他移动场景与动作预览继续反向，否决。
2. 给每个 Visual 场景分别配置 `front_axis`——当前全部现役人物使用同一导出方向，会引入没有
   现实需求的双重配置与漏配风险，否决；未来确有异轴第三方模型时再在导入适配层归一化。
3. 反转 W 输入或 `aim_direction`——会让物理位移、相机相对控制和公共运动数据一起倒置，否决。

## 后果

- 正式角色和动作预览会整体旋转 180°，人物正面重新与真实行进/瞄准方向一致。
- 停止时仍保留最后 `aim_direction`，动作选择、播放速率、碰撞和能力调度不变。
- 旧文档中“模型局部 `-Z` 为正面”的表述属于已证伪约定；本次更新直接相关的运行时注释和
  验收说明，历史记录保留原样以免改写当时证据。
