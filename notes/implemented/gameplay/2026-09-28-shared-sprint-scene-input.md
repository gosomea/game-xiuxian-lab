# Note: 共享疾跑的全场景输入接入

Status: implemented

## 问题

使用者反馈疾跑没有应用到全部场景，并确认它应是全场景复用的统一能力。
`SwordsmanMovement` 已根据共享组件中的疾跑输入选择速度，但镜头实验室与青玉纸白样板没有发送该输入。
实验输入对象将 Shift 列为可选键，移动庭院另存一套按键表，导致场景接入不一致。
此前动作验收只覆盖动作工作台，未验证全部消费场景的输入链路。

## 决策

- 保持疾跑速度选择在共享 `SwordsmanMovement` 内。角色与能力不读取原始键盘，也不识别场景。
- `MovementLabInput` 默认跟踪方向键和 Shift，提供统一的 `sprint_input()` 意图读口；移动庭院也使用该对象。
- 移动清单中的八个场景均向角色公开 API 传递该意图，不设置场景专属疾跑速度。动作工作台预览模式仍关闭实时角色输入。
- 保持站着按 Shift 不移动、松开恢复步行、失焦及重置清输入的语义。御剑仍由既有飞行能力控制速度。
- 从子实验清单逐项加载真实场景，注入按键并推进物理帧，验证步行、疾跑、动画、释放和失焦，防止只验证单个场景造成遗漏。

## 备选方案

- 仅在两个漏接场景补 Shift：可以修复当下症状，但可选按键和庭院独立输入表仍使后续接入容易遗漏。
- 让角色或移动能力直接读取 Shift：键盘会侵入可复用运行时，破坏输入来源与能力执行的分离，也影响预览模式关闭输入。

## 后果

所有使用现役修士的可操作移动实验共享按键与能力。独立二维坊市使用不同二维角色与移动实现，不属于该修士的消费场景。
新增子实验进入清单后自动纳入场景接入回归。运行记录见 [疾跑全场景验收](../../../docs/playtest/2026-09-28-shared-sprint.md)。
