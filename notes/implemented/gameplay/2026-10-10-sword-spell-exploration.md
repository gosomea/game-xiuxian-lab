# Note: 天轮、巨剑与剑雨的施法探索

Status: implemented

## 问题

现有剑法工作台只能比较剑气、定点往返飞剑、身后扇面齐射。使用者于 2026-10-10 授权规划并以三个原生子 Agent 实施天轮剑阵、巨剑镇落、天降剑雨，由主 Agent 集成验收；要求完整施法流程、流畅动画、自然剑运动和帅气表现。现有鼠标选点位于人物高度平面，线段命中只检查 X/Z 最近点处的 Y，不能可靠支持高速垂直落剑；共享表现字段也不能承担多招持续状态。

## 决策

三个方向各为 abilities 下独立叶子包：heavenly_sword_wheel、giant_sword_descent、heavenly_sword_rain。各包包含自己的纯数据 Component、Capability、View 与配对测试；只通过 SwordCastComponent、SwordsmanMotionComponent 与目标数据通信，不跨 Capability 引用。旧三招、角色现役视觉与共享镜头保留。

共享 sword_cast 契约增加真实地面 aim_surface_point / aim_surface_valid / aim_surface_normal，保留 aim_point 的人物高度方向语义；增加 cancel_generation（重置、失焦、退出触发的取消序号）与 feedback_serial / feedback_point / feedback_strength（纯数据反馈请求记录）。各新能力捕获取消序号，取消时失活并清表现；蓄势换招取消，释放后换招继续完成，持续输出不再覆盖其它招的独立 Component。表现阶段的姿势请求只由当前招式写入，避免后台法术抢朝向。

SwordCastTargets 提供三维线段对膨胀竖直目标的最早交叉，以及竖直受限的圆形范围查询。直接命中每把剑每目标最多一次；巨剑贯穿与落地冲击合用本次命中账本，避免同一次镇落重复登记。木桩仍无血量、伤害或胜负。新增落剑在地形接触点停留/消散，不以人物高度为地面。

天轮流程为凝聚、双层圆轮悬剑、释放前转向、沿弯曲轨迹分组加速齐射、收势。巨剑流程为选点与法阵凝聚、完整剑形悬停、锁点镇落、一次落地冲击、残影消散。剑雨流程为选区、上空成阵、明确分批落剑、剑尖接地后衰减、散阵。所有行为时序用 manager_time()，视图只读状态，实际命中不由视觉帧触发。

复用原简化剑几何，在 shared/sword_cast/models 下另存共享版本，原资产保留；新增网格法环、轨迹尾迹与冲击使用 Compatibility 可用路径。法环、剑刃和背景有明暗层次，完整构图保证人物、落点与主要剑可见。巨剑冲击通过 TimeKeeper 请求一次短顿帧，轻剑群不逐剑顿帧；可减弱反馈。运行镜头仍由 CameraRig 唯一写入，法术 View 不直接修改 Camera3D。

执行契约保存在 [方案](../../../docs/10-plans/sword-spell-exploration/plans.md)。共享基础、三条实现分支、集成、最终视觉验收按 DAG 执行；分支 worktree 验收后保留不变。最终检查覆盖旧三招、完整移动/御剑、取消/重置/换招、命中几何与退出清账；连续画面与运动样本用于审查起承转合、轨迹与朝向。

## 备选方案

- 全部变体堆进 SwordArray：持续阶段与落点规则不同，共享输出会互相覆盖，选择独立包；旧扇面保持原行为。
- 每把剑生成 Area3D：放弃能力内确定性 tick 且增加节点和物理依赖，保留批量数据模拟与几何查询。
- 单纯增大命中半径与剑模型：无法表达镇落、落地冲击和自然加速，选择对应空间几何与分阶段运动。
- 为特效改用 Forward+：会改变全部现有视觉与运行基线；首轮沿用 Compatibility 的网格、材质与自建尾迹。
- 三招先共享一个通用法术管理器：目前没有足够验证过的生命周期，不预造框架，只抽取实际复用的输入、几何与视觉工具。

## 后果

三个新方向的参数是探索起点，不构成最终平衡结论；不增加成长、敌人 AI、血量、伤害与胜负。无手指骨的限制保留，施法以肩臂姿态和法阵响应表达，不宣称做出掐诀手型。运行验收与视觉结论由实际证据记录，主观好看不由单元测试替代。
