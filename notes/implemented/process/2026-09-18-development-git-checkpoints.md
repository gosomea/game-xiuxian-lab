# Note: 每轮开发使用本地 Git 提交保存

Status: implemented

## 问题

实验室虽已是独立 Git 仓库，移动、场景与资产开发却长期停留在未提交工作区，缺少可追溯和可恢复的开发记录。

## 决策

按使用者明确要求，本项目持续作为独立 Git 仓库管理。每轮产生文件变更的开发结束前，完成适用检查，并创建本地 Git commit；较长任务在可独立解释的阶段完成后提交。提交包含对应代码、场景、源资产、导出资产、决策记录和必要验收证据，不只执行暂存。

开始工作时检查已有变更，保持其归属；不覆盖、不丢弃他人或使用者的改动。提交前审查文件清单和差异，排除凭据、机器缓存及临时日志。仅咨询或没有文件变更时不制造空提交。

未完成或检查失败但需要保存的工作，可明确标记为 WIP 提交，并记录未完成项与失败证据，不宣称开发完成。提交受阻时如实报告原因和未保存状态。交付时报告提交号、摘要与工作区剩余变更。

此授权覆盖本地 commit，不自动授权 push、强推或改写历史。Git 保存不替代[探索资产保留](2026-09-18-exploration-asset-retention.md)，仍不得通过删除旧资产来整理版本。

## 备选方案

- 仅在最终定版时提交：不适合持续探索，阶段成果缺乏恢复点，不采用。
- 只暂存文件或依赖编辑器历史：不是完整 Git 提交，不能替代开发记录，不采用。

## 后果

本次先保存此前已交付且尚未提交的庭院、群山移动和美术资产，以及资产保留规则。之后每轮开发默认包含本地提交，无需再次征求提交许可。
