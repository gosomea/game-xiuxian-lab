# Note: 探索资产保留与版本替换

Status: implemented

## 问题

实验室需要比较、复用不同探索版本。新模型沿用旧模型导出路径会覆盖旧版本，使保留的旧场景也随之改变；只保留源文件不足以保留可直接使用的旧资产。

## 决策

按使用者明确要求，探索过程中产出的模型、材质、贴图、动画、场景及其源文件和导出资产必须保留。版本被废弃、替换、优化或不再引用，都不是删除资产的理由。

- 在原模型上继续修改时，允许更新该模型及对应导出文件；必须在资产台账说明是原模型迭代。
- 重新建模、新方案或替代版本必须使用独立文件名或版本目录，保留原源文件与导出资产；不得用相同导出路径覆盖原版本，也不得把重新生成新模型称为原模型修改。
- 停用版本保留在原处，或连同必要依赖归档；记录源文件、导出文件、对应场景和替代关系。移动时维护引用，不留下失效路径。
- 清理仅限可再生缓存和临时运行日志，不包括探索资产。Git 历史、截图或生成脚本不能替代源文件与导出资产的保留。
- 所有项目资产必须存放在本仓库并进入 Git 提交，包括各探索版本的模型、材质、贴图、动画、音频、字体、场景、预览图、源文件与导出文件，以及停用和归档版本。不能只留在外部目录、只登记路径或只提交生成脚本；文件较大也不得直接漏交。
- 提交前检查未跟踪与被忽略文件，禁止忽略规则排除项目资产。仅可再生的引擎导入缓存、系统缓存和临时运行日志不作为资产提交；生成的模型、贴图和预览图仍属于资产。

本规则取代[群山视觉重建](../art/2026-09-18-mountain-realm-visual-rebuild.md)中「重建人物但保持原模型路径」的后续执行方式。

## 备选方案

- 只保留 Blender 源文件、需要时重新导出：旧版本无法直接复用，且再导出结果可能受工具版本影响，不采用。
- 删除停用资产、依赖 Git 恢复：探索成果可能尚未提交，也不利于直接比较，不采用。

## 后果

仓库会保留多个探索版本；资产台账负责解释当前使用与停用版本，而不是通过删除文件表达状态。
