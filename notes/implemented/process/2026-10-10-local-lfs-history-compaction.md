# Note: 精简已删除旧人物的本地 LFS 历史

Status: implemented

仅本地发布限制已由使用者随后授权的[完整 LFS 上传与强推](2026-10-10-lfs-remote-publication.md)接替；下文描述精简实施时的范围与验收，限定清单及备份要求继续有效。

## 问题

[完整历史迁移](2026-10-10-historical-lfs-migration.md)保留了所有旧人物版本，因此本地 LFS 共约 9.08 GiB；现有文件对应的唯一内容约 0.97 GiB。使用者选择仅本地开发后，明确同意精简当前目录已删除的旧人物历史。

## 决策

1. 使用者于 2026-10-10 的“ok 精简一下”授权本次限定范围的本地历史改写和对象回收，作为探索资产默认保留规则的例外，不授权删除当前文件或推送远端。
2. 从已有盘点中选择所有本地引用尖端均已没有的旧人物大资产路径：212 个历史 LFS 内容对象、255 个精确路径、8,611,699,289 bytes（8.020 GiB）。青玉纸样板的 `jade_pine.blend1` 与 `jade_rock.blend1` 属环境备份，排除；现有源、导出、归档、环境和动作库全部保留。清单冻结在[实施清单](../../../docs/migrations/2026-10-10-lfs-compaction/plan.json)。
3. 在独立副本实施，先保存包含全部 Git 引用、工作树元数据与 LFS 内容的完整旧数据库。备份仍位于同一磁盘，保留它时实际磁盘释放不等于日常 LFS 逻辑体积的缩减。
4. 对全部本地分支和 Codex 引用统一映射，保留分支、提交数、父子关系和作者/提交者/消息；只从历史树移除清单路径。逐提交独立核对剩余路径、文件模式和 blob 身份，所有引用尖端的树必须与改写前相同。已签名提交无法保留有效签名时停止；不默默移除签名。
5. 核对全部剩余历史指针对应的本地 LFS 文件大小和 SHA-256，仅回收已无任何引用的本次清单内容；既有无引用小暂存对象不顺带删除。移除副本旧 reflog、重新打包，原数据库保留在备份。
6. 主工作区接管前重新检查所有工作树干净、所有分支未产生新提交；改写后的分支尖端文件保持相同，工作树原始文件不重写。其他工作树的分支和索引保留，验证全部工作树状态。若并行工作改变了分支或文件，先吸收并重做核对，不能覆盖。
7. 更新普通 blob 豁免清单的基线提交映射与历史文档链接。继续保持仅本地开发、LFS 过滤器与推送阻断；常规开发不能运行 `git lfs prune`。本次限定回收不推广为后续资产清理规则。

## 备选方案

- 只删 LFS 缓存：历史指针仍引用旧对象，在没有远端对象的情况下形成缺文件版本，不采用。
- 只保留当前快照、重新初始化 Git：会丢掉玩法与工程提交历史，不采用。
- 清理所有历史缺席的大文件：会包含两份环境备份，超出旧人物范围，予以保留。
- 仅清理完全无引用的小暂存对象：约 0.35 MiB，不能解决主要占用，不采用。

## 后果

日常仓库不再提供清单内旧人物历史文件；旧历史只能从独立备份恢复。实际 LFS 缓存由 9.091 GiB 降为 1.071 GiB（包含新增剑法资产），现役内容和当前归档保持不变。主分支及剑法分支的提交号统一改变，旧分支不能合回新历史。后续若决定远端发布，仍须明确授权、上传剩余对象并使用预期旧 SHA 的 `--force-with-lease`。

执行记录、提交映射、完整性与运行时证据见[精简报告](../../../docs/migrations/2026-10-10-lfs-compaction/report.md)。
