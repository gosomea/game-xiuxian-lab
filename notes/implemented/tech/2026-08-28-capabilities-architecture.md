# Note: 运行时采用 Capabilities 能力架构

Status: implemented

## 问题

独立游戏项目最常见的死法是「需求蔓延导致改不动、被迫重构」。玩法广度型游戏（机制多是卖点）会不断往角色/实体上叠加行为：移动方式、主动技能、被动词条、状态效果。用继承或整体式脚本组织时，行为之间互相引用、争抢修改同一状态，加到几十个行为后任何改动都可能弄坏无关机制。

参考证据：《双影奇境》（Hazelight，GDC 2025 演讲）用 Capabilities 架构支撑 150 万行玩法代码、约 1 万个玩法类、任意时刻每玩家约 250 个并行激活的能力，玩法核心团队仅十余人；3 天 Game Jam 产出 100+ 环境互动且大部分保留进正式版。

## 决策

运行时采用三层职责划分，映射到 Godot 如下：

- **Component（纯数据容器）**：Node 子类，只存数据与派生值计算，禁止决策。可被多个能力共享读写。
- **Capability（行为单元）**：Node 子类，遵循五函数触发轴 `_should_activate → _on_activated → _tick_active → _should_deactivate → _on_deactivated`，由 CapabilityManager 每帧按 priority 轮询。激活当帧即执行 `_tick_active`（轴是同帧连续的，否则能力有「延迟一帧生效」的隐藏行为）。多能力并行激活（不是状态机）。
- **GameObject（决策者）**：父 Node + CapabilityManager 子节点，负责组合与调度。

调度器同时持有**逻辑时间**（`elapsed`，随每次 tick 累加 delta）。能力的冷却、持续时长等时序判断读逻辑时间而非墙钟时间，因此无头测试可用手动 tick 精确推进时序。

配套机制：

- **通信纪律**：Capability 之间禁止直接引用（同一功能包内也不例外）；通信只走 Component 共享数据 + TagRegistry 阻塞。阻塞记录 instigator，解除时只移除自己的条目——防止两个系统互掐，例如两个各自请求时停的能力，若不记 instigator，先结束的那个会误删另一个的时停。
- **Sheet**：一组 Capability + Component 打包为场景文件，挂到 GameObject 上即生效、卸下即失效（丹药/阵法/境界表单的统一机制）。格式选型见 [sheet-format](2026-08-28-sheet-format.md)。
- **signal 使用纪律**：仅用于纯数据变化通知（如灵力值变化刷 UI），不承载行为决策——Godot 惯用法与轮询模式的最小阻抗映射，不为纯粹性硬拗。
- 单机游戏砍掉全部网络同步维度（Synced/Local 划分），复杂度减半。

实施顺序纪律：行为攒到 15–20 个、开始互相打架前不预先抽象更多框架层；时间线式调试日志随运行时层第一天建立（词条一多，「哪个被动触发了」不查时间线就是玄学）。

## 备选方案

- **数据导向 ECS（Unity DOTS / UE Mass 路线）**：输在前提不匹配。ECS 的收益在海量实体（百千级）的批处理与缓存局部性；本模板面向「实体少（几十）、机制多」的游戏，轮询开销实测可忽略（Split Fiction：250 能力轮询约 0.5ms/帧）。ECS 还会牺牲「设计师/Agent 挂一个单元即生效」的装配体验。
- **状态机（FSM/行为树）**：输在互斥语义。状态机假设状态互斥、转移显式；修仙类「被动词条并行生效、条件触发互相叠加」天然是并行激活，用状态机会爆炸成转移线地狱。行为树适合 AI 决策，可作为单个 Capability 的内部实现（Compound Capability），不适合做实体行为的顶层组织。
- **不抽象，直接写在角色脚本里**：对深度型游戏（一个机制磨一万小时）成立且更诚实；对广度型游戏，15–20 个行为后必然互相打架，届时再重构的成本远高于第一天立好基类。本模板定位广度型，故不采纳。
- **UE Gameplay Ability System（GAS）**：思想同族（Ability + Tag + 阻塞），但绑定 UE；本模板主用 Godot，取其思想不取其框架。

## 后果

- 代价：每帧轮询的固定开销（小规模可忽略）；输入/移动需为轮询定制；词汇表（Tag/事件清单）成为全局耦合点，必须靠门禁维持纪律；1 万个类量级的检索成本在本模板量级下不会出现。
- 收益：加新机制不重构成型代码；Capability 自包含后可被 Agent 安全批量生产（配合门禁）；「挂载即生效」让 Sheet 机制同时服务丹药、阵法、领域类神通。
- 负面保证：本架构不承诺「游戏好玩」；手感与节奏不可机械验证，靠 playtest（人 + playtest-verify 双轨）。
