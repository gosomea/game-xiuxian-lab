# Note: 装饰面共面导致的跨场景地面闪烁

Status: proposed

类别：art（美术与资产管线）。当前状态：**已确认缺陷，尚未修复**（fix not yet implemented）。

## 问题

使用者在实际运行中报告三处实验的**地面在移动时持续闪烁**（原话包含「剑法实验」「压力」「易懂」，其中「易懂」为对其他实验的观察；入口映射见下表）：

| 报告序号 | 场景 | 场景判定依据 |
|---|---|---|
| 1 | 御剑飞行训练场 `src/levels/experiments/character_movement/sword_flight_course.tscn` | **基于现有入口的推断**：用户原词为「剑法实验」，仓库当前没有已实现的剑法战斗场景（`sword_combat` 仍为 `planned`），故映射到唯一存在的御剑飞行场景；若实际指的是别的入口，需以用户复现为准 |
| 2 | 状态切换压力场 `src/levels/experiments/character_movement/state_transition_lab.tscn` | **明确点名**：用户直接描述的切换/失焦实验 |
| 3 | 移动庭院 `src/levels/experiments/character_movement/movement_garden.tscn` | **基于现有入口的推断**：用户未点名，按上下文推断为庭院；若实际指的是地形接触训练场 `ground_contact_course.tscn`，仍落在同一缺陷族（见下） |

报告只描述现象，未给出截图或逐帧证据；本 note 的现象定性来自只读横向审计与镜头实验室 owner 的像素探针（证据见对应小节）。

### 现象定性

这是**跨场景通用的资产生成/场景表现缺陷**，不是 Godot 引擎缺陷，也不是透明材质排序问题。

机制：**装饰层与承托面共面或相交 ＋ 三个 GLB 的全部 primitives 使用双面材质 ＋ 连续微动的正交相机导致移动时的深度/边缘重新取样闪烁。**

- 共面使两个不透明面在同一深度上竞争（Z-fighting）；双面材质让背面也参与光栅化，没有背面剔除来稳定竞争结果；相机在跟随移动时每帧的采样栅格都在变，于是闪烁在移动中最明显。
- **不写成「静止也必闪」**：冻结相机的静止对照为零差异（镜头实验室 owner 探针：关闭 physics 后连续 6 帧 changed-ish px = 0，144000 采样点）。该缺陷可以被静止画面对照掩盖，评估与回归都必须以**移动中**的画面为准。
- 视觉表现是地面出现随镜头移动而变的摩尔纹/闪面，不是逐帧随机噪点（装饰件的水平抖动量在生成时即固定）。

### 两类共面必须分开处理（否则允许清单会互相污染）

同一份扫描会命中两种几何关系，严重度与修法都不同：

- **A 类：水平装饰层与水平承托面共面**（围边、压顶、铺装、自发光标记）。两片大面积同深度竞争，是本次闪烁的主因，也是最严重的一类；修法是抬升装饰层。
- **B 类：竖直物体的底面正好落在水平地面上**（竹干、柱脚、旗杆底）。接触处是一个小面积水平端盖与大平面的共面，严重度低得多，常见于正常建模；修法是**把物体下沉 2 mm 埋入地面**，而不是抬升。

允许清单必须逐条标注属于 A 类、B 类还是「确实允许」，不能只写「允许」。

### 已确认范围与待扫描范围

- **已确认共面命中**：`sword_flight_course`、`state_transition_lab`、`movement_garden`。
- **同类风险、需一并扫描**：`ground_contact_course`。独立扫描在该 GLB 上命中 **128 组**共面对，其中：`bamboo_*_stem_*` ↔ `ground_ground_*` 属 **B 类**（竹干正好立在地面上，预期存在、按 B 类下沉处理）；`tools/art/generate_ground_contact_course.py:364-368` 的 `step_*_top` 底面正好等于台阶顶面属 **A 类**（同一约定漏改点）。同一场景的 `ground_*_top` 因为埋入 5 mm 才免于共面。因此：**即使使用者第三处实际指的是地形接触训练场，结论不变**——仍属同一缺陷族，扫描与修复范围相同。
- **对照命中数**（同一扫描口径，footprint > 0.01 m²、gap ≤ 1.5 mm）：`sword_flight_course` 9 组、`state_transition_lab` 22 组、`ground_contact_course` 128 组；`movement_garden` 由本次独立扫描命中 131 组（口径为水平重叠 ≥0.05 m² 且垂直重合 ≤1.5 mm）。
- **未审**：`mountain_realm` / `peak_courtyards`。它们的台账已记录过 2 cm 抬升约定（见下），预期不命中，但必须用同一扫描确认。
- **明确不是缺陷的部分**：三个场景的程序地面/装置全部是 `StaticBody3D` + `BoxShape3D`，**没有任何 MeshInstance**（`movement_garden.gd:201-212`、`state_transition_lab.gd:281-305`、`sword_flight_course.gd:153-169`）。所以问题**不是**「GLB 视觉地面与程序地面重复」，只是 GLB 内部的装饰层互相共面。

### 与镜头实验室 owner 实机/探针证据的交叉核对

镜头实验室 owner 独立跑过同一批场景的像素级探针，结论与本 note 的机制表述一致（证据在 `~/.cache/game-xiuxian-lab/ground-flicker/`，仓外）：

| 探针 | 结果 | 说明 |
|---|---|---|
| 冻结相机（关闭 physics），御剑场景连续 6 帧 | changed-ish px = **0**（144000 采样点） | 静止不闪，与本 note 的「不武断写静止必闪」一致 |
| 冻结相机 + 关阴影 / + 改 bias / + 关 MSAA | 三者仍为 **0** | 排除阴影偏差与 MSAA 是主因 |
| 相机仍在收敛（跟随未静止） | 每帧 changed-ish px = 208 / 394 / 562 / 688 | 相机一动就开始变化 |
| 移动中 10 帧 | changed 0.35% → 8.90%，maxdelta 达 178 | 含正常视差，不能单独作为闪烁量；需与近景小区域对照 |
| 移动中关闭阴影 | 仍 changed 0.47% → 1.13% | **关阴影不能消除**，进一步排除阴影为根因 |
| GLB 共面扫描 | sword 9 组（`landing_*_rim`、`step_*_lip`、`takeoff_mark*`）、state 22 组（含 `Bridge rail post ↔ Jade disc`）、ground 128 组 | 与本 note 的扫描互为独立复现 |
| 材质 `doubleSided` | sword 9/9 材质、state 8/8、ground 14/14 | 全双面确认 |

相机冻结为 0 差异这一点同时说明：**只用单张静止截图验收会得到假阴性**，必须用移动中对照（见验收标准第 3 条）。

## 提案

1. **先做静态扫描，不动资产**：为 `src/**/*.glb` 增加一个只读共面扫描（标准库解析 GLB 的 JSON chunk 与节点变换，判定「水平重叠 ≥0.05 m² 且垂直重合 ≤1.5 mm 且两材质均非透明」）。先产出**允许清单**：列出所有命中对，逐对标注「A 类应修 / B 类下沉 / 确实允许（写明理由）」。允许清单是修复的前提，避免把有意的叠层（例如自发光标记压在台面上）与缺陷混为一谈。
2. **逐个源生成器修复并重导**：在四个脚本里把 A 类装饰层的底面改为**高于承托面 2 mm 以上**（沿用 `mountain_realm` 已验证的 2 cm 量级更稳），B 类物体的底面改为**下沉 2 mm 埋入地面**；或整层埋入只留可见面高出。**唯一例外**：`state_transition_lab` 的 `Bridge near/far span` 是**可走面**，抬升会与碰撞盒产生可见台阶，应改为缩短可见重叠段（或给桥顶做收边），**不得**改碰撞数值。
3. **材质收敛（可选、与 2 独立）**：给实体盒/柱类材质启用背面剔除，双面只保留给旗帜、薄片等确实需要的件。
4. **重导并保留全部旧资产**：**不删除、不覆盖旧资产为新方案**；本轮属于「在原模型上继续修改」，允许更新同一 `.blend`/导出件，但必须在对应的 `docs/art/*/asset_ledger.md` 注明修改内容与日期；若某个件选择重新建模，则另存文件名或版本目录，禁止覆盖旧资产。依据根 AGENTS.md「探索资产不得删除」与[探索资产保留](../../implemented/process/2026-09-18-exploration-asset-retention.md)。
5. **禁止手改 GLB**：所有修复都从生成器重跑得到；`.glb` 与其 `.import` 是生成物，手改会被下一次重跑覆盖，也会让台账哈希失效。
6. **不先改相机/手感来掩盖**：不靠拉近近平面、改跟随速度、加模糊或调曝光把闪烁藏掉；相机与输入手感不是本缺陷的根因，先改它们会让后续无法判断修复是否真的生效。
## 备选方案

- **只改运行时相机参数（近平面/远平面/投影）**：不采用。三场景的闪烁与 `far = 120 / 300 / 400` 的差异无关（`far` 最小的庭院同样闪烁），且相机是正交投影、深度线性；共面才是根因，改相机属于掩盖。
- **写 shader 给地面加 polygon offset / 深度偏移**：不采用。逐材质打补丁会把缺陷固化进运行时材质，且无法覆盖「同一个 GLB 在别处被复用」的情况；根因在资产，修在资产。
- **只修当前反馈的三个入口**：不采用。共面来自四个生成器共享的同一写法，只修单处必然遗漏其余同源问题；`ground_contact` 已确认有同类漏改点（`step_*_top`），只改被反馈的场景会把它留到下一轮复发。
- **删掉装饰层网格来消除共面**：不采用。装饰层是观感的一部分（围边、压顶、铺装、自发光标记），删掉会让实验场景失去可读性；正确做法是保留几何、改高度关系。
- **声明这是引擎缺陷并等待引擎修复**：不采用。三个 GLB 全部双面 + 精确共面是可复现的资产条件，同一引擎下的 `mountain_realm` 用 2 cm 抬升即可避免，说明引擎行为正确。
- **把三个场景的装饰件整体重做为合并单网格**：不采用。超出当前探索范围，且会破坏「装置名 = 网格名」这一支撑 playtest 可视/碰撞对齐断言的命名契约（见 `docs/art/ground_contact_course/asset_ledger.md`）。

## 验收标准

按顺序执行，前一步不过不进入下一步：

1. **静态扫描**：共面扫描对 `src/**/*.glb` 运行，输出命中清单与允许清单（A/B/允许三分类，每条有文字理由）。修复完成后，命中数 = 允许清单条数。
2. **生成器断言**：四个生成器在导出前对本次导出的网格自检，命中未允许的共面即失败退出并打印冲突对名字（纯 Python，不依赖引擎）。
3. **真实运行对照**：三个已确认场景各自执行「移动中」与「冻结静止」两组对照。冻结静止组连续帧应为零差异；**移动组的帧间差异必须回落到与同场景无装饰地面区域相同的量级**，不能只凭单张静止截图判断（冻结对照已证明单张静止图会假阴性）。
4. **受影响场景全量回归**：`run_all.py --with-tests`、七个子实验的 standalone playtest、庭院与群山回归全部通过；资产哈希与台账同步更新。
5. **门禁（若新增）**：若把共面扫描固化为 `tools/verify/verify_gltf_overlays.py` 并纳入 Tier 0，必须同时满足根 AGENTS.md 工程约定第 6、7 条——在 `tools/verify/negative_control.py` 增加「故意共面案例被真实拒绝」的负向用例，且失败输出必须带 `fix=` 指向具体生成器脚本。未满足这两条前，扫描只作为一次性检查工具，不声称是门禁。

## 风险

- **抬升量过小会被浮点吃掉**：2 mm 在导出精度与深度缓冲下应足够，但 1 mm 级别在部分平台未必稳定；修复时统一采用 2 mm 以上，并靠扫描而非肉眼确认。
- **可走面不能抬**：`state_transition_lab` 的桥面若跟着抬升，站立高度与碰撞盒会出现视觉错位；这是本提案中唯一需要「改可见几何形状而非高度」的地方，最容易改错。
- **A/B 分类是人工判断**：把 A 类误标成 B 类会导致修法错误（该抬的反而下沉）。允许清单逐条必须给出理由并由审查者复核。
- **改生成器会改变导出哈希**：`docs/art/*/asset_ledger.md` 中的 sha256 与字节数必须同步更新，否则台账失真；旧 `.blend1` 等探索版本不得连带清理。
- **静止对照可能让人误判为已修复**：本缺陷在冻结相机时为零差异，任何只截单张静止图的验收都不能证明问题消失。
- **允许清单可能被滥用**：把真实共面写成「允许保留」会让扫描失去意义；允许清单必须逐条给出理由，并由审查者复核。
- **未审场景仍有同类点**：`mountain_realm` / `peak_courtyards` 尚未扫描，在本 note 落地修复前不能声称「全仓地面闪烁已消除」，只能声称「已确认四处已处理」。
- **本 note 的现象描述来自使用者口述 + 只读静态审计 + 镜头实验室 owner 探针**：缺少使用者本人的移动中录像；若后续实机复现与本 note 的机制描述不符（例如冻结静止时也有差异），应以实机复现为准并更新本 note，而不是反向解释证据。

## 影响面（架构）

- 纯表现/资产管线问题：**不新增 Capability**，**不改三能力与角色物理**，唯一物理提交点不变。
- 修复只落在 `tools/art/generate_*.py`（源几何）与重导出的资产；运行时代码原则上不动。若扫描固化为门禁，则按验收标准第 5 条补负向控制与 `fix=`。
- 依据：[角色移动子实验套件](../../implemented/gameplay/2026-09-18-character-movement-subexperiments.md)（七个子实验的职责边界与验收口径）；[角色移动与庭院](../../implemented/gameplay/2026-09-18-character-movement-garden.md) 为历史前置决策，仅在需要追溯庭院资产来源时参考。
