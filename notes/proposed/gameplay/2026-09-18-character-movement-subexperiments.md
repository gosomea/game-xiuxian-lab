# Note: 角色移动子实验套件

Status: proposed

## 问题

角色移动目前由 `movement_garden.tscn` 与 `mountain_realm.tscn` 同时承担能力验证、镜头、动作表现、地形接触、御剑高低差和综合美术展示。群山宗门已经形成满意的综合场景，继续直接在其中调试镜头或动作，会让局部实验受复杂地形与美术干扰，也增加场景编排和角色能力之间的耦合。顶层实验目录目前每个模块只有一个入口，也无法如实表达一个移动大项下的多个子实验及其状态。

## 提案

将“角色移动”保留为一个顶层模块，顶层入口改为移动子实验目录；各子实验围绕一个可回答的问题独立运行。现有庭院与群山资产和场景全部保留，不覆盖、不删除。

子实验地图如下：

| 子实验 | 核心问题 | 定位 |
|---|---|---|
| 镜头实验室 | 跟随、缓动、死区、前视、缩放、旋转与遮挡怎样配合移动？ | 灰盒对比场 |
| 人物动作工作台 | 待机、起步、跑动、转身、跳跃、御剑、降落及其过渡是否清楚？ | 空白动作棚 |
| 地形接触训练场 | 斜坡、台阶、墙角、窄路和边缘上的移动与碰撞是否稳定？ | 物理训练场 |
| 御剑飞行训练场 | 起飞、升降、悬停、穿越、转向和落点选择是否可控？ | 立体路线场 |
| 状态切换压力场 | 能力切换、失焦、重置、碰撞和边缘时机是否正确清账？ | 可视化压力场 |
| 移动庭院 | 小范围地面移动和旧资产回归 | 已有基线 |
| 群山宗门 | 三项移动能力在完整空间与美术中的组合体验 | 已有综合场景 |

顶层 `character_movement` 条目只指向移动子实验目录。子实验清单使用角色移动专属的数据文件维护 `id / title / question / status / scene`；未有可运行场景的条目不得伪造路径或标为就绪。暂不把子实验塞成新的顶层玩法模块，也不为了一个嵌套目录改造通用 `core/`。

架构边界：

- `SwordsmanMovement`、`Jump`、`SwordFlight` 仍是仅有的三项移动 Capability；各能力只经 `SwordsmanMotionComponent` 意图字段与 TagRegistry 协作，禁止相互直接引用。
- 角色根仍是唯一 `move_and_slide()` 提交点。子实验不得直接写角色 `velocity`、移动意图或 Capability 内部状态，只能调用角色公开输入 API。
- 动作表现属于 `game/actors/swordsman/`，只读取 `actual_velocity / on_floor / flight_active / aim_direction` 等公共运动数据，不把动画帧、动作播放完毕或场景节点作为物理规则。
- 镜头比较、障碍布局、调试 HUD 和实验控制属于对应 `levels/experiments/character_movement/` 子场景。在实验结论稳定并出现第二个真实消费者前，不提前抽入 `core/`；确需复用的稳定镜头行为再进入独立叶子包。
- 全局 `empty_stage.tscn` 继续保持中性。人物动作工作台是移动模块自己的完整场景，可以复用环境资源，但不能把移动专属输入、HUD 或动作逻辑写回全局空白工作台。
- 每个场景脚本保持单一职责；重复且语义稳定的实验 UI 或输入编排才抽成移动实验专属组合节点。组合优先于深继承，不建立“万能移动实验基类”。
- 新增模型、动画、贴图、预览和导出资产全部另存并进入 Git；既有资产不能被覆盖或删除。

推进顺序按可玩性风险，而不是按技术基建排序：

1. 人物动作工作台与镜头实验室先形成可运行代表链路。
2. 审计场景职责、三 Capability 边界和真实输入后，再推广到御剑飞行与地形接触训练场。
3. 状态切换压力场复用前述结论，覆盖边缘时机和清账。
4. 最终在移动庭院做小范围回归，在群山宗门做组合验收；不把子实验的调试 UI 带入群山宗门。

## 备选方案

- 继续在群山宗门中增加全部调试区域：局部问题难以隔离，且会破坏已经满意的综合场景，不采用。
- 每个子实验作为顶层模块：会把一个移动问题拆成多个伪玩法模块，污染八大模块目录，不采用。
- 先建立通用实验框架、万能镜头系统和公共基类：当前消费者不足，容易把尚未验证的假设固化为共享 API，不采用。
- 直接修改全局空白工作台承载人物动作：会让其他模块的中性起点依赖角色移动，不采用。
- 为跑动和动作切换新增 Capability：纯表现不具备独立玩法生命周期；当前先由表现层消费运动数据，不采用。若以后引入玩家主动冲刺、资源消耗或独立互斥，再单独评审新能力。

## 验收标准

- 顶层角色移动入口可进入子实验目录，目录只为实际存在的场景提供运行入口，并保留庭院与群山入口。
- 人物动作工作台可用真实输入观察待机、移动、转向、跳跃、御剑、升降、关闭御剑与落地；HUD 能区分输入意图、实际速度与三项能力状态。动作表现不会改变物理结果，移除表现节点后三项能力仍工作。
- 镜头实验室能在同一灰盒中比较至少固定跟随、平滑跟随、前视/死区和手动缩放；旋转镜头后移动方向仍按屏幕基解释，切换镜头策略不修改角色或 Capability。
- 地形接触训练场覆盖平地、坡度、台阶、墙角、窄路与边缘；御剑训练场覆盖多层落点、升降、悬停、通道与低天花；压力场覆盖失焦、重置和关键同帧切换。
- 新场景均可独立启动和返回子实验目录；场景脚本不出现第二个物理提交点，不直接引用具体 Capability 类，不修改 `core/`。
- 单元测试、Tier 0 门禁、既有庭院与群山回归继续通过；新增子实验提供真实运行证据和精简验收报告。
- 所有新增资产、场景、源文件、导出文件和最终截图进入 Git；每个可解释阶段创建本地 commit。

## 风险

- 镜头策略和角色输入基准互相影响；比较时必须同时记录实际相机基和角色移动结果，避免只凭截图判断。
- 当前人物没有骨骼和脚掌 IK，动作工作台可能首先暴露模型与绑定能力不足；应如实记录，不让动画层接管物理来掩盖问题。
- 子实验数量增加后可能复制输入和 HUD；只有重复语义经过两个场景验证后才抽取组合节点，避免过早共享和后期散乱同时发生。
- 子实验目录改变顶层角色移动入口，需要保留直接启动旧场景的能力，并对实验清单、返回路径和进度状态做回归。
